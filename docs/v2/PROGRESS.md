# Summa 2.0 实施记录

## 基线与范围

以 `main` 的 `f70d075`（v0.4.2）为稳定基线，在
`codex/summa-2.0` 开发。沿用 Flutter、Riverpod 和 Drift。产品优先保证
Android 离线记账、数据可导出、账务准确及历史可追溯。

## 应用标识与迁移

- Android 应用 ID、namespace 和 Kotlin 包使用 `com.maniaamae.summa`，
  Dart package 使用 `summa`。开发版本为 `2.0.0-dev.1+7`。
- Android 将旧包和新包分开安装，分别保管应用文件。从旧版「设置 → 数据与备份」
  导出完整 JSON 到应用外，再用新版同一页面的外部备份恢复功能迁移。先核对账户余额、
  历史记录及关联，再决定是否卸载旧版。完整备份包括账本数据，主题、语言等设备偏好
  及旧应用内的本地备份列表需要分别管理。
- 新备份使用 `summa_full_backup`，记录 SQLite Schema 版本。完整备份协议仍为
  Version 1，可读取旧版 `ledgerpro_full_backup`；恢复保留账户、分类、交易 ID、
  时间、备注、币种、关联账户及软删除状态。导出读取单一数据库快照，恢复在事务内执行。
- 新安装使用 `summa.sqlite`。当前应用私有目录中若已有旧数据库文件，仍可原址
  打开，SQLite 会一并处理其日志文件。Schema 7 新增分录视图和查询索引，没有重写
  原始账户、分类或交易表。Schema 6 到 7 的 DDL 与 SQLite 版本号一起提交。
  同一账本再次打开时查到相同的原始数据和分录。

## Phase 1 进度

- `ledger_entries` 保存经济事件。`ledger_account_postings` 投影真实账户的
  分录，账户余额展示、新增及编辑校验、余额校准共用这套分录。按借方为正、贷方为负
  表示整数最小货币单位，展示负债时翻转符号。
- `ledger_postings` 补齐非账户分录。正常的现金、信用及受托资金消费分别记录
  账户变动和消费对方分录。等额转账、借入和本金还款只涉及账户。每笔分录按币种
  平衡，软删除的交易不参与。现有期初余额继续保存在账户表中。
- 缺少对方账户、币种冲突或信用账户入账性质不明的旧交易可通过 `needs_review`
  查询。保持旧版账户余额含义和原始记录，无法分类的对方分录记为
  `unclassified`。新增异币种划转需要未来提供两边的结算金额。当前记账表单和
  汇总仍以人民币为主，完整的多币种录入、显示、换算与估值界面尚待实现。

## 后续交付顺序

1. 完成 Phase 1 财务核心。扩展为可持久化的多分录交易，支持资金归属、原始及结算
   金额、退款关联、应收款、拆分、待入账状态和冲销。让指标及债务趋势直接使用分录，
   为旧版语义不明确的交易提供待复核摘要。余额校准仍沿用旧版行为，后续应通过显式
   调整分录和余额检查点保留差额与日期。
2. 推进其余 P0。实现基于真实样本的微信、支付宝及通用 CSV/XLSX 适配器、导入批次
   与幂等去重、匹配和人工复核、可撤销导入、基础分类规则及账户对账。
3. 交付 P1。完成预算与外部额度、订阅与周期计划、债务与应收款、储蓄目标与资金
   分配、分析、现金流预测和首页体验。计划数据应在确认入账后才影响实际指标。
4. 核心稳定后交付 P2 报告、高级规则及导出。完成真实设备和数据迁移验证后准备
   Release Candidate。P3 的 Android 通知辅助记账作为后续版本候选。

## 验证

- 60 项 Flutter 测试通过，包含旧版及新版完整备份恢复、恢复失败回滚、Schema 6
  文件升级及重复打开、账户余额一致性、分录平衡和跨币种输入保护。
- `flutter analyze --no-pub` 通过。Android Debug APK 可构建，包名、显示名称和
  启动 Activity 经 APK 检查。Android API 36 模拟器中已验证两个包名可并存。
- 在模拟器走完外部备份选择、预览与恢复流程。最终构建冷启动后读取已恢复的合成交易，
  金额 ¥23.45、账户余额 ¥76.55 与预期一致。真实设备和真实账本留待发布前验证。
