# 产品基础设计

**简体中文** | [English](../product-foundation.md)

## 产品边界

Summa 是一款完全离线、面向单用户的个人账本，Android 是首个交付平台。核心功能不需要登录、服务器或网络权限。

首个可用版本包括：账单录入与编辑、两级分类、资产与负债账户、日/周/月汇总、基础图表、带预览的严格 JSON 导入，以及 JSON、CSV 和数据库导出。

## 记账模型

Summa 不把所有资金流入都等同于劳动收入，也不把偿还负债重复计算为新的支出。

### 交易类型

一笔交易表示一次经济事件：

- `expense`：消费或损失，例如饮食和交通。
- `income`：个人净资产增加，并明确记录收入来源。
- `borrowing`：负债增加，同时目标个人资产增加同等金额；它不是收入，也不改变流动净资产。
- `repayment`：个人资产减少，同时目标负债减少同等金额；它不是支出，也不改变流动净资产。
- `transfer`：两个个人资产账户之间等额转移，不影响收入、支出或净资产。

收入来源初步包括劳动所得、家庭支持、赠予、报销、退款、投资收益和其他。这些来源用于统计，不改变收入本身的记账机制。

### 账户与负债

账户表示价值存放或所欠的位置。为了让自定义名称不会干扰余额计算，当前使用五种稳定账户类型：现金、银行账户、支付钱包、信用负债，以及委托/共享/授权资金。

用户可以在这些类型下自由添加账户。初始个人账户为现金、银行卡、支付宝和微信；初始负债账户为花呗、白条、抖音月付和美团月付；亲情卡单独归入委托/授权资金。朋友欠款等个人应付款可以使用自定义负债账户表示。应收款的余额方向与负债相反，未来应使用专门模型，避免被误记为负债。

使用花呗购物时，记录一笔由信用负债账户支付的支出，因此花呗负债增加。日后偿还花呗时，记录从银行卡或钱包流向花呗的还款，而不是再次记录支出。

为了特定采购收到的钱可以存入委托资金账户，采购支出从该账户扣除。剩余资金可以继续保留其委托属性；当用户确认它已经成为个人所有时，也可以明确记为家庭支持或赠予。这样不会把所有家庭资金误报为劳动收入。

分期使用一个负债账户加分期元数据表示。购买行为只确认一次，偿还本金属于还款，手续费和利息则单独记为支出。

### 分类

支出和收入分类在当前版本都采用两级结构：

```text
一级分类 -> 二级分类
```

每笔需要分类的交易必须选择二级分类，一级分类由它自动确定。内置“未分类”始终可用，避免因为无法精确归类而阻止记账。已经被账单引用的分类只做归档，不直接从数据库中删除。一级和二级的“其他”始终置底，新建分类会排在兜底项之前。

账户回答“钱从哪里来、到哪里去”，分类回答“这次经济事件的用途或来源是什么”，两者保持独立。常用支出一级分类都包含受保护的“其他”二级分类；全局“其他 -> 未分类”是在一级分类也无法确定时的最终兜底。

### 余额汇总

移动端余额概览将四个数值分开显示：

- 个人流动资产：属于用户的现金、银行卡和支付钱包余额。
- 委托或授权资金：可以使用但不属于个人资产的亲情卡、采购款等。
- 待偿负债：信用账户与个人应付款当前未偿还的正数余额。
- 流动净资产：个人流动资产减去待偿负债。

固定资产不计入当前版本的日常余额，未来可作为独立的非流动资产组，并建立明确的估值规则。

首页优先展示本月支出、本周支出、累计记录支出和流动净资产；详细账户分组与余额放在“账户”页面。

### 更正与删除规则

编辑账单会一次性替换类型、金额、日期、分类、相关账户和备注，并基于新账本重新计算受影响余额。删除账单采用软删除：记录仍保存在数据库中，但不再影响列表、报表和余额。

删除账户实际是停用账户。历史账单仍可显示它的名称，新账单不能再选择它。恢复默认账户只会重新启用相同稳定 ID 的内置记录，不会重置余额或交易关联。

软删除用于保证数据完整性，目前不需要可见的回收站。常规查询会排除已删除记录，因此它们不会常驻内存，只会让本地 SQLite 文件缓慢增长。未来可以在确认备份后增加清理和压缩操作；在审计与恢复需求确定前不自动清理。

### 余额安全规则

个人资产和委托资金不能被支出到零以下。还款金额不能超过付款账户余额或目标负债余额。直接计入负债账户的收入视为减少负债，同样不能把负债减到零以下。这些规则由数据仓库原子执行，而不只存在于界面层，因此未来的 JSON、OCR 和语言模型导入也无法绕过。编辑账单时，校验会先排除旧记录的影响，再检查替换后的新记录。

## 金额与时间规则

- 金额不使用二进制浮点数保存。
- 使用整数最小货币单位，并配合 ISO 4217 币种代码。
- 时间戳保存为确定时刻，并保留录入时区偏移。
- 每个持久化实体都有稳定 ID 和创建、更新时间。
- 财务数据优先使用软删除或审计记录。

## 结构化导入约定

JSON 是规范交换格式，每个载荷都有 `schema_version`。导入流程为：解析、校验、显示易读预览、用户确认、原子提交。未来 OCR 和语言模型可以生成同一 JSON，但不能绕过校验或直接写入数据库。

CSV 用于日常分析，不是无损备份。数据库快照与带版本的 JSON 才是恢复格式。

首版导入结构可以接受单个交易对象、交易数组或下面的标准外壳。金额使用十进制字符串，时间使用 ISO 8601，分类路径使用“一级/二级”。账户名不存在时会在同一事务中自动创建。`account_kind` 和 `target_account_kind` 可以指定 `cash`、`bank`、`wallet`、`creditLine` 或 `entrustedFunds`；省略时，普通账户推断为钱包，借入与还款会推断为所需的负债/钱包角色。

```json
{
  "schema_version": 1,
  "transactions": [
    {
      "type": "expense",
      "amount": "28.50",
      "occurred_at": "2026-09-09T12:30:00+08:00",
      "category": "饮食/午餐",
      "account": "支付宝",
      "account_kind": "wallet",
      "note": "午餐"
    },
    {
      "type": "borrowing",
      "amount": "1000.00",
      "occurred_at": "2026-09-09T13:00:00+08:00",
      "account": "朋友欠款",
      "account_kind": "creditLine",
      "target_account": "微信",
      "target_account_kind": "wallet",
      "note": "向朋友借款"
    }
  ]
}
```

批量导入遵循全有或全无。解析后的记录会进入预览，每一条都可以编辑或移除；最终数据库事务仍会重新执行余额安全校验。新账户也属于同一事务，因此失败批次不会留下交易或孤立账户。导入新资产账户的历史支出时，系统会把其期初余额设为确保这段导入历史合法所需的最小金额。

## 报表与导出

日报、周报、月报和年报都是基于原始交易即时计算的视图，不复制出额外的归档账单。移动端报表还包括收支结余、借入和还款总额、支出趋势、支出/收入分类饼图和负债走势；趋势图使用日期横轴和金额纵轴提供大致标尺。

导出范围可选本周、本月、本年、全部或自定义日期，格式可选 JSON、CSV 或 Markdown，随后通过系统分享/保存面板处理。只有出现真实需求时，未来才考虑不可变的报表快照。

## 分类管理

支出和收入的两级分类都可以新增、重命名、排序和归档。创建一级分类时会自动建立受保护的“其他”子分类。归档不会删除分类记录，因此历史账单继续保留原标签。恢复默认分类只重新启用缺失的内置分类，不影响自定义分类。

## 转账

`transfer` 是两个不同个人资产账户之间移动资金的独立交易类型。它等额减少来源账户并增加目标账户，不影响收支报表；来源余额不足时会拒绝执行。流向负债或委托资金的操作应使用各自的记账流程，不能伪装成普通转账。

## 完整备份与恢复

Summa 完整备份 JSON 包含全部账户、期初余额、分类、账单、稳定 ID、归档标记和软删除标记。覆盖恢复会精确重建快照；合并恢复会更新稳定 ID 相同的数据，同时保留仅存在于本机的记录。两种模式都在数据库事务中执行，并受本次启动周期的自动备份保护。

本地备份节点分为自动和手动两组。每次打开软件后，第一次成功修改账本前会保留修改前状态；如果操作校验失败，则删除这份临时快照。自动组最多保留最新五个节点。手动本地节点不会自动轮换，可以重命名、删除、合并或用于覆盖恢复。两组都位于应用私有文件目录，卸载或恢复出厂会删除它们，因此外部导出仍是可靠的异机备份方式。

“重置所有账单与账户”会删除全部交易与自定义账户，并恢复余额为零的默认账户，同时保留分类和备份节点。“恢复出厂设置”还会恢复默认分类并删除全部本地备份节点。两项操作都需要明确的破坏性确认。
